输入网址按下回车后发生了什么

从 DNS 到 TCP、TLS、HTTP，再到页面渲染：一次访问背后的完整旅程。

一句话结论回车之后，浏览器要先「问路」（DNS），再「敲门」（TCP 三次握手），再「说悄悄话」（TLS 协商密钥），最后才「点菜」（HTTP 请求）——页面是最后一步。

    每个阶段在干嘛

    ① DNS：把名字变成地址

    网络路由认的是 IP，人记的是域名。浏览器先查自己和系统的缓存，没有就问 DNS 解析器（通常是运营商或 8.8.8.8 之类），得到 IP。

    ② TCP：先确认「彼此能听见」

    三次握手：客户端 SYN → 服务器 SYN-ACK → 客户端 ACK。双方交换初始序列号，约定好可靠传输的起点。

    ③ TLS：在公开线路上建立私密通道

    TLS 1.3 里，客户端 ClientHello（带密钥交换份额），服务器回 ServerHello 并发出证书和 Finished，客户端验证证书后发 Finished，之后的数据全部加密。1 个往返即可（1-RTT）。

    ④ HTTP：真正的「点菜」

    在加密通道里发 GET / HTTP/1.1 等请求，服务器回状态码（如 200）、响应头和正文 HTML。

    ⑤ 渲染

    浏览器解析 HTML 构建 DOM，解析 CSS 构建 CSSOM，合成渲染树，布局、绘制；遇到 <img>、<script> 又会发起新的请求，重复上面的流程（常常复用已建好的连接）。

    常见误区

    「HTTPS 就是 HTTP 加了个锁图标」HTTPS 是 HTTP 跑在 TLS 之上，TLS 握手发生在任何 HTTP 内容发送之前。
    「DNS 查询是加密的」传统 DNS 是明文的，网络中间人能看到你查了哪些域名；DoH/DoT 才加密。
    「握手每次都要完整来一遍」浏览器会复用连接（keep-alive）、TLS 会话恢复，所以第二次访问更快。
