越权：水平 / 垂直 / IDOR

少了一道「这是不是你的」检查

定义类比成因危害防御审计视角本地实验靶场小测验误区报告模板
一句话定义越权（访问控制失效）是指：用户做了本不该被允许的事——看了别人的数据（水平越权 / IDOR），或用了更高权限的功能（垂直越权）。
本课只讲原理、防御与审计思路。所有演示都是浏览器里的假数据模拟；不提供针对真实目标的攻击载荷清单，也请只在自己搭建的环境或获得授权的范围内验证。

🏠 生活类比

酒店刷卡电梯：认证 = 你有房卡（证明你是住客）；授权 = 房卡只能到你那一层。IDOR 就是"房卡能进电梯，但电梯没检查你要去的楼层"。

🔍 成因：问题到底出在哪

"登录了"≠"有权限"。许多接口只验证了前者。越权在 OWASP Top 10 2021 中排名第一，因为它是逻辑缺失，扫描器很难发现。

水平越权 / IDOR

同级别用户之间互相访问。IDOR（不安全的直接对象引用）指接口直接用客户端传来的 ID 取对象。

// 有漏洞：只验证登录，不验证归属
@login_required
def get_order(order_id):
    return db.orders.get(order_id)      // 谁的订单都给

垂直越权

低权限用户调用高权限功能。前端隐藏了按钮，但接口没校验角色。

@app.route("/admin/users/delete")   // 没有 @admin_required
def delete_user(uid): ...

多步流程越权

直接请求流程的后一步，绕过前面的审批/支付检查。

// 第 3 步"确认发货"接口只检查登录，不检查第 2 步"已付款"状态

💥 危害与等级

严重垂直越权到管理功能；批量读取/修改全站用户敏感信息（身份证、手机号、订单）。
高水平越权可读取或修改他人隐私、资金相关数据。
中只能读取非敏感数据，或需要极难猜测的 ID。
决定等级的因素数据敏感度、读还是写、是否可批量、是否需要登录。

🛡 防御与修复

修复原则：每个接口、每次访问、服务端都做授权；默认拒绝。

// 对象级：查询时就带上属主条件
def get_order(order_id):
    order = db.orders.get(order_id, owner=current_user.id)
    if order is None: abort(404)       // 既不存在也无权 → 统一返回，防止探测
    return order

// 功能级：集中式的权限装饰器/中间件，路由默认要求权限
@require_role("admin")
def delete_user(uid): ...

// 不要信任客户端传来的 role / userId / isAdmin 字段
// ID 用不可预测的 UUID 只是加分项，不能代替授权

🧐 怎么判断自己安全？代码审计视角

  • 列出所有"带 ID 的接口"，逐个问：服务端有没有把这个 ID 和当前用户关联校验？
  • 有没有接受客户端传来 userId/role 这类字段的写接口（批量赋值/Mass Assignment）？
  • 管理接口是否与普通接口隔离，权限校验是集中还是靠各处手写？
  • 测试方法（在授权范围内用两个自己的测试账号）：A 的资源用 B 的会话访问，看返回。

✅ 小测验

⚠ 常见误区

「前端隐藏了就没人能调」抓包或直接构造请求，完全不经过前端。
「登录就有权限」认证与授权是两件事。
「隐藏的接口地址别人不知道」靠隐蔽性不是安全；前端代码、文档、日志都能暴露地址。

📝 SRC 报告里怎么描述（虚构示例模板）

下面是完全虚构的示例（example.test 不是真实站点）。注意三点：标题含等级与位置、复现步骤最小化且只用自己的账号、说明影响但不扩大验证。写法细则见 漏洞报告与沟通。

标题：【高危】example.test 订单详情接口水平越权（虚构示例） 目标/接口：GET https://shop.example.test/api/orders/{id}（虚构） 漏洞概述：接口只校验登录，未校验订单归属，可通过修改 id 读取其他用户订单（姓名、手机号、地址）。 复现步骤： 1. 注册两个测试账号 A、B，分别各下一单，记下订单号 a、b。 2. 以 A 的会话请求 /api/orders/b，返回 B 的订单详情。 3. 仅使用自己的两个账号验证，未遍历或读取任何真实用户数据。 影响：订单号为自增整数，理论上可被批量遍历，涉及全部用户的收货信息。 修复建议：查询时加入属主条件；非属主返回 404；订单号改用不可预测标识作为附加措施。 自评等级：高危（涉及个人敏感信息，可批量）。
