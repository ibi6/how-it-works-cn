CSRF 跨站请求伪造

借你的登录态，替你做了你没想做的事

定义类比成因危害防御审计视角本地实验靶场小测验误区报告模板
一句话定义CSRF 是指：你登录了 A 网站后，访问了恶意的 B 网站，B 让你的浏览器向 A 发出一个请求；浏览器会自动附上 A 的 Cookie，A 以为是你本人操作。
本课只讲原理、防御与审计思路。所有演示都是浏览器里的假数据模拟；不提供针对真实目标的攻击载荷清单，也请只在自己搭建的环境或获得授权的范围内验证。

🏠 生活类比

你在银行有一张"自动盖章的授权卡"（Cookie），只要有人拿着你的名义的单子到柜台，卡就会自动盖章。骗子给你寄一张看似无害的传单，传单背面其实是"转账单"，你一"翻面"（点击/加载），章就盖上了。

🔍 成因：问题到底出在哪

根因：浏览器自动携带 Cookie，而服务器仅凭 Cookie 判断"是不是你"，无法区分"你主动发的"与"别的网站诱导你发的"。

改状态用 GET

GET 请求会被图片、链接等无需交互地触发。

// 有漏洞
GET /transfer?to=bob&amount=100   // 仅靠 Cookie 认证

POST 无令牌

外站的表单可以自动提交到你的站点。

// 有漏洞：POST 改密码，只验证 Cookie
POST /user/password   body: new=...

Cookie 无 SameSite

老的默认行为是跨站也会带 Cookie；现代浏览器默认 Lax 但不应依赖默认值。

Set-Cookie: sid=abc   // 未显式声明

💥 危害与等级

高资金/账号相关操作（转账、改密码绑定邮箱）可被伪造 → 账号接管。
中修改资料、发帖、关注等有一定影响的写操作。
低登出、无关紧要的偏好设置（多数 SRC 不收）。
决定等级的因素被伪造的操作有多敏感、是否需要额外验证（原密码/验证码）、有无现成防护被绕过。

🛡 防御与修复

修复原则：让服务器能确认"这个请求确实来自我自己的页面"。

// 1) SameSite：跨站请求不带 Cookie（首选的第一层）
Set-Cookie: sid=...; HttpOnly; Secure; SameSite=Lax   // 敏感站可用 Strict

// 2) CSRF Token：表单里嵌入随机令牌，服务端比对（外站读不到你的页面）
<input type="hidden" name="csrf" value="{{ session.csrf_token }}">
if request.form["csrf"] != session["csrf_token"]: abort(403)

// 3) 校验 Origin / Referer 是否为本站
// 4) 改状态绝不用 GET；敏感操作二次验证（原密码/短信）
// 5) 纯 JSON API：要求自定义头（跨站无法在不触发预检的情况下带）

🧐 怎么判断自己安全？代码审计视角

  • 所有"改状态"的接口：是 GET 吗？有没有 CSRF Token / Origin 校验？
  • Cookie 是否显式设置 SameSite？是否存在 SameSite=None 的必要性？
  • Token 是否绑定会话、是否可预测、是否可被其他接口泄露？
  • CORS 是否错误地允许任意来源并带凭证（会放大风险，见第 4 课）。

✅ 小测验

⚠ 常见误区

「用 POST 就不会有 CSRF」外站表单可以自动提交 POST。
「有 Referer 检查就够」Referer 可能为空，须定义空值策略；仍建议配合 Token。
「CSRF Token 放在 Cookie 里就行」需要服务端比对且来源不可被攻击者设置，否则失效。

📝 SRC 报告里怎么描述（虚构示例模板）

下面是完全虚构的示例（example.test 不是真实站点）。注意三点：标题含等级与位置、复现步骤最小化且只用自己的账号、说明影响但不扩大验证。写法细则见 漏洞报告与沟通。

标题：【中危】example.test 修改绑定邮箱接口缺少 CSRF 防护（虚构示例） 目标/接口：POST https://account.example.test/api/email/bind（虚构） 漏洞概述：绑定邮箱接口仅依赖 Cookie，无 Token，Cookie 无 SameSite；外站页面可诱导已登录用户提交。 复现步骤： 1. 登录自己的测试账号，抓取绑定邮箱请求，确认没有 Token、Referer 校验。 2. 在自己控制的本地页面放置一个指向该接口、字段为自己第二个测试邮箱的表单，用同一浏览器打开并提交。 3. 账号绑定邮箱被修改（只在自己的测试账号上验证）。 影响：配合"邮箱找回密码"可接管账号。 修复建议：加入 CSRF Token；Cookie 设置 SameSite=Lax；绑定需二次验证。 自评等级：中危~高危（取决于可否接管账号）。
