漏洞详解 6/15

不安全的文件上传

「头像」被当成了「程序」来处理

定义类比成因危害防御审计视角本地实验靶场小测验误区报告模板
一句话定义文件上传漏洞是指：网站对上传文件的类型、内容、文件名、存放位置和访问方式控制不当，导致不可信文件被服务器当作可执行内容处理，或造成其他危害。
本课只讲原理、防御与审计思路。所有演示都是浏览器里的假数据模拟；不提供针对真实目标的攻击载荷清单，也请只在自己搭建的环境或获得授权的范围内验证。

🏠 生活类比

快递站收包裹。只看包裹上写的"内容：书"就收下并放进能自动运转的机器房，结果包裹里是一台会自己开动的机器。正确做法：开箱检查、换成统一标签、放进只读仓库。

🔍 成因：问题到底出在哪

风险来自四个环节：类型判断、文件名、存放位置、访问方式，任何一个信任了客户端，都会出问题。

只信客户端声明

只检查前端 JS 的扩展名，或只看请求里的 Content-Type（这两个都由客户端提供，可任意伪造）。

// 有漏洞
if request.files["f"].content_type in ["image/png","image/jpeg"]:
    save(request.files["f"], "/var/www/html/uploads/" + original_name)

保留原文件名 / 可执行目录

文件被存进 Web 目录，且以用户给的扩展名保存，服务器可能按扩展名当脚本执行；还可能有路径穿越（见第 8 课）。

// 文件名 shell.php 被保存到 Web 根目录，Web 服务器会执行 .php

其他危害

SVG/HTML 文件含脚本 → 存储型 XSS；超大文件/压缩炸弹 → 拒绝服务；图片处理库漏洞；文件内容里的敏感信息（EXIF 位置）。

// 允许上传 svg 并从主域名下提供访问 → 同源的 XSS

💥 危害与等级

严重上传的脚本在服务器执行（远程代码执行）。
高存储型 XSS（上传 HTML/SVG 且同源访问）；覆盖任意文件。
中文件内容校验缺失导致存储垃圾、存储炸弹、隐私信息泄露。
决定等级的因素文件能否被执行或解释、存放域名、访问是否需要认证。

🛡 防御与修复

修复原则：不信客户端、重命名、隔离存放、不可执行。

// 1) 扩展名白名单（而不是黑名单）
ALLOWED = {"png","jpg","jpeg","gif","pdf"}

// 2) 检查真实内容：读文件头（魔数）并用图像库重新编码
img = Image.open(f); img.verify(); img = img.convert("RGB"); img.save(out)

// 3) 重命名为随机名，扩展名由服务端根据检测出的类型决定
name = uuid4().hex + ".png"

// 4) 存放在 Web 根目录之外或对象存储；
//    通过单独的、无脚本执行能力的域名（如 static-cdn.example）提供，
//    并设置：Content-Disposition: attachment 或 X-Content-Type-Options: nosniff
// 5) 限制大小与数量；杀毒；上传目录禁止执行权限

🧐 怎么判断自己安全？代码审计视角

  • 上传的文件最终存哪里？Web 服务器会不会执行该目录下的文件？
  • 扩展名与 MIME 的判断依据是客户端还是服务端内容检测？
  • 文件名是否被保留？有没有路径穿越与特殊字符处理？
  • SVG / HTML / PDF 是否允许？从哪个域名访问？同源还是独立域名？

✅ 小测验

⚠ 常见误区

「检查了 Content-Type 就行」这个头由客户端设定，随便写。
「黑名单禁止 .php 就安全」扩展名有大小写、双扩展名、其他可执行类型，白名单才可靠。
「图片重新压缩就没事」要保证重新编码输出，且存放访问方式也要隔离。

📝 SRC 报告里怎么描述（虚构示例模板）

下面是完全虚构的示例（example.test 不是真实站点）。注意三点：标题含等级与位置、复现步骤最小化且只用自己的账号、说明影响但不扩大验证。写法细则见 漏洞报告与沟通。

标题：【高危】example.test 头像上传未校验真实类型且存放于可执行目录（虚构示例） 目标/接口：POST https://app.example.test/api/avatar（虚构） 漏洞概述：头像上传仅校验请求头的 Content-Type，文件以原名保存到 Web 目录下。 复现步骤： 1. 在测试账号上传一个内容为纯文本的"演示文件"，将 Content-Type 声明为 image/png，成功。 2. 访问返回 URL，文本被按原样返回，保存路径含原始文件名，说明未重命名未重新编码。 3. 未上传任何可执行内容，只用纯文本证明校验缺失，并向厂商说明如替换为脚本的潜在影响。 影响：如目录允许脚本执行，可导致服务器代码执行（需厂商确认，未验证）。 修复建议：扩展名白名单 + 魔数检测 + 重编码 + 随机命名 + 存放于不可执行位置。 自评等级：高危（校验缺失 + 可能的执行条件）。
