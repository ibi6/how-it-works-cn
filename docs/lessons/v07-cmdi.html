命令注入

输入被拼进命令行，变成了额外的命令

定义类比成因危害防御审计视角本地实验靶场小测验误区报告模板
一句话定义命令注入是指：程序把用户输入拼接到操作系统命令里并交给 shell 执行，用户输入中的特殊字符让 shell 多执行了其他命令。
本课只讲原理、防御与审计思路。所有演示都是浏览器里的假数据模拟；不提供针对真实目标的攻击载荷清单，也请只在自己搭建的环境或获得授权的范围内验证。

🏠 生活类比

你对智能音箱说"播放 ××，然后打开前门"。音箱不分前后，一并执行。设计问题：它应该只把"歌曲名"当作歌曲名。

🔍 成因：问题到底出在哪

根因：通过 shell 解析一整条字符串。shell 对 ; | && $() 反引号等有特殊含义。

拼接后交给 shell

最经典写法。

// 有漏洞：ping 检测功能
os.system("ping -c 1 " + host)
// host = "example.com" 正常
// host 含 ; 或 | 时，后面的内容被当成新命令

不经意的调用

图片处理、压缩、PDF 转换、Git 操作等调用外部程序时拼接了文件名/参数。

subprocess.run("convert " + filename + " out.png", shell=True)

参数注入

即使不经过 shell，用户可控的参数开头是 - 也可能被程序当作选项。

subprocess.run(["tar", "xf", user_file])   // user_file 以 - 开头会被当选项

💥 危害与等级

严重服务器上执行任意命令：读取配置/密钥、植入后门、横向移动。
高受限执行（沙箱、低权限账号）。
决定等级的因素运行账号的权限、是否有回显、是否在容器隔离内。

🛡 防御与修复

修复原则：能不调用命令就不调用；必须调用时，不用 shell，用参数数组，并校验参数。

// 1) 优先使用语言/库的原生功能（如用 HTTP 库代替 curl，用图像库代替 convert）

// 2) 必须调用时：参数数组 + 不经过 shell
subprocess.run(["ping", "-c", "1", host], shell=False, timeout=5)

// 3) 严格校验输入格式（白名单正则）
if not re.fullmatch(r"[A-Za-z0-9.-]{1,253}", host): abort(400)

// 4) 用 "--" 终止选项解析：["tar","xf","--",user_file]
// 5) 低权限账号运行 + 容器隔离 + 出站限制

🧐 怎么判断自己安全？代码审计视角

  • 搜索：os.system、exec、popen、Runtime.exec、shell=True、反引号。
  • 参数里是否含用户可控内容？是否只是"格式上看起来安全"？
  • 运行进程的账号权限是什么？是否在容器中？

✅ 小测验

⚠ 常见误区

「过滤分号和管道就行」还有换行、反引号、$() 等多种写法。
「命令执行没回显就没危害」盲注入依然可以执行动作（写文件、外联）。
「容器里就不怕」容器逃逸与凭据泄露仍可能造成危害，隔离只是减小影响。

下面是完全虚构的示例（example.test 不是真实站点）。注意三点：标题含等级与位置、复现步骤最小化且只用自己的账号、说明影响但不扩大验证。写法细则见 漏洞报告与沟通。

标题：【严重】example.test 网络诊断功能命令注入（虚构示例） 目标/接口：POST https://ops.example.test/api/ping {"host": ...}（虚构） 漏洞概述：诊断接口把 host 拼进命令行执行。 复现步骤： 1. 提交正常主机名，响应含 ping 输出。 2. 在授权范围内提交 host 为"正常主机名 + 分隔符 + 一条无害只读命令"（如输出固定字符串的 echo），响应中出现该字符串，证明被 shell 解析。 3. 验证后立即停止：未读取文件、未执行其他命令。 影响：服务器任意命令执行。 修复建议：改用参数数组调用；host 白名单校验；降权运行；容器隔离。 自评等级：严重（任意命令执行）。
