路径穿越（目录遍历）

../ 让你走出了本该待着的文件夹

定义类比成因危害防御审计视角本地实验靶场小测验误区报告模板
一句话定义路径穿越是指：程序用用户给的文件名拼出文件路径来读写文件，用户在文件名里用 ../（返回上一级目录）跳出了预期目录，读取或写入了其他位置的文件。
本课只讲原理、防御与审计思路。所有演示都是浏览器里的假数据模拟；不提供针对真实目标的攻击载荷清单，也请只在自己搭建的环境或获得授权的范围内验证。

🏠 生活类比

你被允许去图书馆"借阅区"的书架拿书。书单上写"上一层的上一层的……保险室里的文件"，管理员没检查路径就去拿了。

🔍 成因：问题到底出在哪

根因：拼接路径后没有验证最终位置仍在允许的目录内。

下载/预览接口

常见于 /download?file=xxx。

// 有漏洞
path = "/var/www/files/" + request.args["file"]
return read(path)
// file 含 ../ 时，实际路径会跳出 files 目录

解压（Zip Slip）

压缩包内的文件名含 ../，解压时写到了目标目录之外。

for entry in zip.entries:
    write("/data/unzip/" + entry.name, entry.data)   // entry.name 可含 ../

编码绕过的错误防御

只在编码前做字符串替换，服务器后续再解码一次。

file = file.replace("../", "")   // 替换一次容易被绕过，且需考虑 URL 解码顺序

💥 危害与等级

高读取源码、配置文件、密钥、数据库连接串，进而扩大攻击面。
严重写入型穿越（上传/解压）可覆盖任意文件，导致代码执行。
中仅能读取无敏感内容的系统文件。

🛡 防御与修复

修复原则：先规范化（解析 ../、符号链接），再检查结果是否仍在基目录下；或干脆不用用户提供的路径。

// 1) 最佳：不让用户传路径，传 ID，服务端映射到文件
file = db.files.get(file_id)

// 2) 必须用文件名时：规范化后校验前缀
base = os.path.realpath("/var/www/files")
target = os.path.realpath(os.path.join(base, name))
if os.path.commonpath([base, target]) != base: abort(403)

// 3) 用框架提供的安全函数（如 send_from_directory），并校验解压路径
// 4) 进程用最小权限运行，敏感文件不可读（纵深防御）

🧐 怎么判断自己安全？代码审计视角

  • 所有读写文件、读取模板、解压、下载接口：路径里有没有用户可控片段？
  • 校验是在"规范化之后"吗？URL 编码、双重编码、符号链接、Windows 反斜杠是否处理？
  • 进程账号能读哪些敏感文件？

✅ 小测验

⚠ 常见误区

「把 ../ 替换成空字符串就行」一次性替换可被嵌套写法绕过，应基于规范化结果判断。
「只读功能没什么危害」配置文件里的密钥一旦泄露，影响远超读文件本身。
「Windows 才有这问题」所有操作系统都有。

标题：【高危】example.test 附件下载接口路径穿越（虚构示例） 目标/接口：GET https://doc.example.test/download?file=（虚构） 漏洞概述：file 参数直接拼接到基目录，未做规范化校验。 复现步骤： 1. 下载自己上传的附件，确认请求形式为 file=文件名。 2. 在授权范围内，将 file 改为指向上一级目录下一个明确的、非敏感的测试文件（由厂商提供或自己在测试环境创建的标记文件），成功读取。 3. 没有尝试读取任何系统敏感文件。 影响：可读取服务器上基目录以外的文件，如配置文件（未验证）。 修复建议：ID 映射或规范化后校验；最小权限运行。 自评等级：高危。
