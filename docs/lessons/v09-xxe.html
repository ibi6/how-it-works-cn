XXE：XML 外部实体注入

XML 解析器被"邀请"去读它不该读的东西

定义类比成因危害防御审计视角本地实验靶场小测验误区报告模板
一句话定义XXE 是指：应用用默认配置的 XML 解析器解析用户提供的 XML，而解析器支持"外部实体"功能，于是可以被诱导去读取本地文件或发出网络请求。
本课只讲原理、防御与审计思路。所有演示都是浏览器里的假数据模拟；不提供针对真实目标的攻击载荷清单，也请只在自己搭建的环境或获得授权的范围内验证。

🏠 生活类比

你收到一份表格，里面写着"此处内容请参见抽屉里的文件 X"，秘书老老实实去抽屉取出文件、抄进表格再回给你。XML 的 DTD / 实体就是这种"参见"机制。

🔍 成因：问题到底出在哪

XML 标准里允许在文档开头用 DTD 定义"实体"，实体可指向外部资源（本地文件、URL）。很多解析器默认开启这个特性，而业务根本用不到。

接收 XML 的接口

SOAP、旧式 API、SVG/Office 文档解析、SAML 登录。

// 有漏洞：Java 默认配置
DocumentBuilder db = DocumentBuilderFactory.newInstance().newDocumentBuilder();
Document doc = db.parse(userInputStream);

概念示例（教科书级）

文档里声明一个实体指向本地文件，再在内容里引用它。解析器会把文件内容替换进去。

<!DOCTYPE order [ <!ENTITY x SYSTEM "file:///etc/hostname"> ]>
<order><item>&x;</item></order>

💥 危害与等级

高读取服务器本地文件（配置、密钥）。
高SSRF：解析器代发请求访问内网。
中"十亿笑声"：实体嵌套膨胀导致拒绝服务。
决定等级的因素能否回显、能读哪些文件、是否有网络出站限制。

🛡 防御与修复

修复原则：禁用 DTD 与外部实体（业务通常完全不需要）。

// Java
factory.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
factory.setFeature("http://xml.org/sax/features/external-general-entities", false);
factory.setFeature("http://xml.org/sax/features/external-parameter-entities", false);
factory.setXIncludeAware(false); factory.setExpandEntityReferences(false);

🧐 怎么判断自己安全？代码审计视角

  • 项目里哪些地方接收/解析 XML（含 SOAP、SAML、SVG、Office 文档、RSS）？
  • 解析器的安全特性是否被显式设置？框架版本的默认值是什么？
  • 解析器是否来自 defusedxml 等安全封装？

✅ 小测验

⚠ 常见误区

「我没用 XML，所以没事」你的依赖或文件格式可能在用。
「XML 解析器默认就安全」很多语言的默认并不安全，需显式关闭。
「只读文件，没什么」配置与密钥一旦泄露后果很大。

📝 SRC 报告里怎么描述（虚构示例模板）

下面是完全虚构的示例（example.test 不是真实站点）。注意三点：标题含等级与位置、复现步骤最小化且只用自己的账号、说明影响但不扩大验证。写法细则见 漏洞报告与沟通。

标题：【高危】example.test 订单导入接口 XXE（虚构示例） 目标/接口：POST https://erp.example.test/api/import（虚构） 漏洞概述：导入接口使用默认配置的 XML 解析器，接受 DOCTYPE 声明。 复现步骤： 1. 提交含有一个"内部实体"定义（只是普通文本替换）的 XML，响应中出现替换后的文本，证明 DTD 被处理。 2. 不尝试外部实体读取文件；说明理论上可通过外部实体读取本地文件。 影响：若启用外部实体，可读取服务器文件、发起内网请求（未验证）。 修复建议：禁用 DTD 与外部实体；升级解析库。 自评等级：高危（以内部实体验证 DTD 被处理为依据，保守评估）。
