开放重定向

你的网站成了骗子的"跳板"

定义类比成因危害防御审计视角本地实验靶场小测验误区报告模板
一句话定义开放重定向是指：网站根据 URL 参数（如 ?next=）把用户跳转到任意地址，而没有校验目标是否可信。
本课只讲原理、防御与审计思路。所有演示都是浏览器里的假数据模拟；不提供针对真实目标的攻击载荷清单，也请只在自己搭建的环境或获得授权的范围内验证。

🏠 生活类比

小区门卫指路："您要去哪？我带您去。"骗子问："带我去 XX 小区的假保安亭。"因为是门卫亲自带的，访客就以为那里也是小区的一部分。

🔍 成因：问题到底出在哪

登录后跳回原页面、退出登录、单点登录回调、短链、"点击离开本站"提示页都会用到跳转参数。

直接使用参数

最常见。

// 有漏洞
next = request.args.get("next")
return redirect(next)

弱校验

只检查"是否以 / 开头"或"是否包含本站域名"。

if next.startswith("/"): redirect(next)
// "//evil.example" 也以 / 开头，会被浏览器当作协议相对的外部地址

白名单写得不严

用 "包含" 或 "以...开头" 判断域名，被拼接的域名绕过。

if "example.com" in next: ...   // evil-example.com.attacker.test 也包含

💥 危害与等级

中钓鱼：链接域名是可信站点，用户容易相信；配合伪造登录页窃取凭证。
高配合 OAuth 回调 redirect_uri 校验不严，可导致授权码/令牌泄露 → 账号接管。
低单纯开放跳转，无敏感上下文：很多 SRC 视为低危或不收。
决定等级的因素是否能与 OAuth/SSO 等敏感流程结合，是否需要用户交互。

🛡 防御与修复

修复原则：只允许跳转到站内的相对路径，或白名单内的完整地址。

// 1) 最佳：不接受 URL，只接受一个"页面标识"，服务端映射
PAGES = {"home": "/home", "orders": "/orders"}
return redirect(PAGES.get(request.args.get("to"), "/home"))

// 2) 必须接受路径时：解析后严格检查
u = urlparse(next)
if u.scheme or u.netloc or not next.startswith("/") or next.startswith("//") or "\\" in next:
    next = "/home"

// 3) 外链跳转：白名单域名 + 中间提示页
// 4) OAuth：redirect_uri 必须与注册值完全匹配（精确匹配，不用前缀/包含）

🧐 怎么判断自己安全？代码审计视角

  • 搜索 redirect、Location、window.location 与参数名 next/url/redirect/return/to。
  • 校验使用的是"解析后的主机名精确匹配"，还是字符串包含/前缀？
  • OAuth/SSO 的回调地址是否精确匹配？

✅ 小测验

⚠ 常见误区

「只是跳转，没危害」它让钓鱼链接带着可信域名；与 OAuth 结合更严重。
「包含域名就算校验」域名可被拼接或作为子域/路径出现。
「前端校验就行」攻击者直接构造链接，不经过你的前端。

📝 SRC 报告里怎么描述（虚构示例模板）

下面是完全虚构的示例（example.test 不是真实站点）。注意三点：标题含等级与位置、复现步骤最小化且只用自己的账号、说明影响但不扩大验证。写法细则见 漏洞报告与沟通。

标题：【低危 / 中危】example.test 登录页 next 参数开放重定向（虚构示例） 目标/接口：GET https://login.example.test/login?next=（虚构） 漏洞概述：登录成功后跳转至 next 参数指定的任意 URL。 复现步骤： 1. 构造 next 为一个自己控制的、无害的外部页面，用测试账号登录。 2. 登录成功后浏览器被跳转到该外部页面。 3. 没有搭建仿冒登录页，没有对他人发送链接。 影响：可用于钓鱼；是否可与 OAuth 流程结合需厂商评估。 修复建议：只允许相对路径或白名单；OAuth redirect_uri 精确匹配。 自评等级：低危~中危（取决于是否与敏感流程结合）。
