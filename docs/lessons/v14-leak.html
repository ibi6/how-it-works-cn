敏感信息泄露

不该给的，多给了

定义类比成因危害防御审计视角本地实验靶场小测验误区报告模板
一句话定义敏感信息泄露是指：应用在响应、错误页、静态文件、日志或代码仓库里，暴露了不该对外的数据，如密钥、内部路径、用户隐私、调试信息。
本课只讲原理、防御与审计思路。所有演示都是浏览器里的假数据模拟；不提供针对真实目标的攻击载荷清单，也请只在自己搭建的环境或获得授权的范围内验证。

🏠 生活类比

前台回答访客时，顺手把内部通讯录、保险柜密码贴在桌上，还把写着密码的便签丢进了没有碎纸机的垃圾桶。

🔍 成因：问题到底出在哪

泄露往往不是"黑客破解"，而是开发或运维时的疏忽：

接口多返回

直接把数据库对象序列化返回，包含密码哈希、内部字段、他人的联系方式。

// 有漏洞
return jsonify(user)     // user 里含 password_hash、phone、internal_note

错误与调试信息

生产环境开着 debug；错误页显示堆栈、SQL、文件路径、版本。

app.run(debug=True)      // 生产环境

遗留文件与仓库

备份文件（.bak、.zip）、.git 目录、.env、日志、前端 JS 里硬编码密钥、公开代码仓库里的 Token。

/static/.git/config   /backup.zip   /.env

💥 危害与等级

严重泄露可直接使用的凭证（云密钥、数据库密码）。
高大量用户隐私（手机号、身份证、地址）。
中内部结构、版本号、路径，为其他攻击提供情报。
低极少量非敏感的版本信息（常常不收）。
决定等级的因素信息的敏感度、数量、是否可直接利用、是否需要认证。

🛡 防御与修复

修复原则：最小暴露：只返回必须的；生产环境关闭调试；密钥不进代码。

// 1) 接口用专门的输出对象（DTO），只列出需要的字段
return {"id": u.id, "name": u.name}

// 2) 生产环境：关闭 debug；统一错误页，只返回请求 ID，详细信息写服务端日志

// 3) 部署：Web 服务器禁止访问隐藏文件与备份；发布流程剔除 .git/.env/备份

// 4) 密钥管理：环境变量或密钥管理服务；仓库开启 secret scanning；一旦泄露立即轮换

// 5) 日志脱敏：不记录密码、令牌、完整身份证号
// 6) 响应头中去掉不必要的版本信息（辅助）

🧐 怎么判断自己安全？代码审计视角

  • 接口响应与数据库模型对比：是不是整个对象都返回了？
  • 生产配置：debug、堆栈回显、目录列表。
  • 仓库与构建产物：有没有 .env、密钥、.git、备份、source map？
  • 日志里是否有敏感值？密钥是否被硬编码？轮换机制是否存在？

✅ 小测验

⚠ 常见误区

「删了文件就没事」Git 历史、缓存、镜像都可能留着副本。
「前端不显示就行」响应里有，别人就能看到。
「版本号泄露不算漏洞」单独通常低危，但会降低攻击成本；具体看规则。

📝 SRC 报告里怎么描述（虚构示例模板）

下面是完全虚构的示例（example.test 不是真实站点）。注意三点：标题含等级与位置、复现步骤最小化且只用自己的账号、说明影响但不扩大验证。写法细则见 漏洞报告与沟通。

标题：【中危】example.test 用户信息接口返回多余敏感字段（虚构示例） 目标/接口：GET https://app.example.test/api/users/me（虚构） 漏洞概述：接口除展示字段外还返回 password_hash 与 internal_note，前端未使用。 复现步骤： 1. 登录自己的测试账号，查看 /api/users/me 响应。 2. 响应包含密码哈希、内部备注、完整手机号。 3. 只查看自己账号的数据。 影响：若与越权漏洞组合，可批量获取他人数据；哈希本身可能被离线破解。 修复建议：使用输出白名单；移除敏感字段；手机号脱敏。 自评等级：中危。
